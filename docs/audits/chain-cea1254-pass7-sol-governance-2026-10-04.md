## G01 — Accepted genesis staking settings are disconnected from effective staking rules

**Priority:** P2 medium. **Classification:** observed source mismatch; production regression pending. **Preconditions:** a freshly initialized chain using an otherwise valid genesis whose typed economic settings differ from the compiled constants, plus normal delegation/undelegation/claim operations. The repository's shipped genesis already supplies such an unbonding period; no malformed field or restart fallback is required.

`ValidatorConstraints.unbonding_period_blocks` is an accepted, required `u64` field ([genesis/src/lib.rs:166](../../crates/torus-genesis/src/lib.rs#L166)). The shipped [devnet genesis:42](../../devnet/genesis.json#L42), [weighted testnet genesis:43](../../testnet/genesis-weighted-base.json#L43), and [genesis test fixture:632](../../crates/torus-genesis/src/lib.rs#L632) declare **604,800 blocks**. Initialization and `chain_config()` do not propagate this value into staking. `StakingManager::new` accepts only the state backend ([staking.rs:29](../../crates/torus-economics/src/staking.rs#L29)); normal undelegation assigns `release_block = current_block + UNBONDING_PERIOD` ([staking.rs:188](../../crates/torus-economics/src/staking.rs#L188)). That constant is seven days divided by the two-second target, i.e. **302,400 blocks** ([types.rs:335](../../crates/torus-economics/src/types.rs#L335)).

The native Undelegate handler passes the actual block height into that method ([native_executor.rs:7478](../../crates/torus-bridge/src/native_executor.rs#L7478)). ClaimUnbonded calls the ordinary staking claim with the current height ([native_executor.rs:7515](../../crates/torus-bridge/src/native_executor.rs#L7515)); maturity checks the persisted release height ([staking.rs:260](../../crates/torus-economics/src/staking.rs#L260)). Consequently, a user undelegating at height 100 gets release height **302,500**, and can reclaim there, whereas the supplied genesis period implies **604,900**. The mismatch is 302,400 blocks; the nominal two-second time difference is seven days. This is a valid normal lifecycle, not a slash-avoidance sequence.

Those four shipped values happen to match their compiled defaults. Their ordinary counterexamples require explicit valid nondefault values: e.g. permanent APY 600 is still paid as 500, or a configured 50-bps commission step still accepts a 100-bps increase after cooldown. They are grouped under G01, not counted separately. A repository Rust-use search found declarations/fixtures but no operational reads of these fields. `min_self_delegation` has a separate partial propagation into `ChainConfig.min_stake` ([genesis.rs:512](../../crates/torus-genesis/src/lib.rs#L512)), while registration uses its constant; this report does not promote a separate claim about intended validator ranking semantics.

**Provenance and distinction.** Historical ECON-PF-16 discusses converting economic durations/APY to a canonical two-second timebase; its fix explains the compiled 302,400 value, but does not establish that accepted genesis overrides are applied. The shipped fixture retained 604,800. Historical Astra genesis findings concern canonical identity collisions, not these typed economic settings. F19 concerns configuration selection on restart; G01 occurs on fresh initialization with an unchanged valid genesis. F27/E01 concerns approved governance changes writing unused ASCII parameter rows; G01 concerns initial typed fields that never reach staking/reward consumers. No matching configuration-contract finding was located in the comparison material. Absence from reviewed reports does not prove global novelty.

**Regression expectations.** Parse and initialize a real genesis with an explicit unbonding period, construct the production execution configuration, then submit valid signed Delegate/Undelegate/ClaimUnbonded actions through block execution. Require the stored release height to equal undelegation height plus that period, a claim one block earlier to fail without changing principal, and a claim at the configured height to credit exactly the principal once. Include the shipped 604,800 fixture and a shorter valid period. For APY, seed real permanent stake and cross a boundary, asserting the expected configured emission; for multiplier, submit a proposal and inspect recorded voter weight; for commission, register/update through native handlers after the normal cooldown, checking the configured bounds.

Either support these declared fields through one canonical persisted economic configuration, or reject noncanonical values and make the fixed protocol rules explicit in schema/templates. Merely changing the 604,800 fixture resolves that fixture's mismatch but leaves accepted nondefault settings misleading. Configuration activation/upgrade behavior needs an explicit decision before implementing a fix.

It cannot catch a disagreement with genesis. [claim_unbonded_tests.rs:68](../../crates/torus-bridge/tests/claim_unbonded_tests.rs#L68) exercises the actual Delegate/Undelegate/ClaimUnbonded executor and contains pre-maturity, exact-maturity, partial, multi-validator and CoreWriter cases, but creates an ad hoc context and uses the same compiled period; it never loads the genesis override. This is a configuration-to-caller coverage gap, not absence of claim tests.

## Historical F09 qualification — Abstain ignores even present positive snapshots

This is explicitly Astra round-1 section 4, **not a new finding**. Yes/no dispatch calls `cast_vote` and abstention dispatch calls `cast_vote_abstain` ([native_executor.rs:7990](../../crates/torus-bridge/src/native_executor.rs#L7990)). Yes/no uses `compute_vote_weight_at` ([governance.rs:823](../../crates/torus-economics/src/governance.rs#L823)); Abstain instead uses live `compute_vote_weight` ([governance.rs:882](../../crates/torus-economics/src/governance.rs#L882)). Therefore F09 regression coverage must include existing positive-snapshot voters, not just previously unstaked addresses and missing rows.

An ordinary user who had 100 stake at proposal creation and legitimately changes it to 200 during voting gets Abstain weight 200 but Yes/No weight 100. Hold aggregate supply fixed with compensating ordinary stake changes when testing this ballot distinction, so the separate moving quorum-denominator issue does not confound the assertion. Abstention contributes to quorum ([governance.rs:935](../../crates/torus-economics/src/governance.rs#L935)) while leaving yes/no tallies untouched. Uniform snapshot lookup for all ballot options is needed in the existing F09-family fix. Tests should inspect stored vote weight and quorum status for all three options; a serialized `snapshot_block` assertion alone does not exercise the lookup.
