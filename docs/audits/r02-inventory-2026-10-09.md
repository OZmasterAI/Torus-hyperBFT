### (2) Error plumbing that exists
- Readers: PositionManager (get_position / get_native_balance / positions_for_trader / get_cum_volume) return
  `Result<_, CoreError>` and keep Ok(None)/default separate from Err. StateBackend returns `StateError`
  (RocksDb / InvalidData / Io / ...). CoreError has `State(StateError)` and `Borsh(String)`. OracleManager::get_price
  returns Err for absence (NoOraclePrice) as well as for faults, so callers must split them. EconomicsError has
  `is_local_fault()` (State | Borsh). CoreError has no equivalent yet; add `CoreError::is_local_fault()` (State | Borsh | MissingCf).
- Halt path: `NativeExecContext.fatal_error: Option<String>` (NE:3659). It is set by the book/margin-config loaders, worker panic,
  cache flush, begin_block_oracle global reads, run_liquidations, and `latch_local_fault` / `econ_err` (NE:9305-9323). app.rs checks it
  three times in execute_committed_block_with (after the batches APP:2381, after CoreWriter+liquidations APP:2428, after
  gov/fees/epoch APP:2446). It then sets `exec_failed` (fail-stop, no flush, block not marked applied). The pre-native
  due-check also latches exec_failed directly (APP:2056-2064).
- NativeActionResult (NE:50) has no fatal variant; execute()/execute_batch return results only. So A-sites in handlers
  should latch `ctx.fatal_error` (first fault wins) and may return any result: the block never flushes. Reader-side
  sites that have no `&mut ctx` (AccountReader, MakerAccountSource, phase2_* helpers, batch_verify callback) need a
  fault cell (`OnceLock<String>`/`Mutex<Option<String>>` on the reader or BlockSums) that is drained into ctx.fatal_error
  after the phase, or a Result return. The app.rs session/nonce sites can set exec_failed directly, as the due-check does.
