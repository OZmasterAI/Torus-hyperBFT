# s83-s85 bench campaigns: market count, root skip, running hash, open-order limit, vote-after-body — 2026-10-03

Twelve campaign dirs under `~/bench-results-matched/`, run 2026-09-30 to
2026-10-03 (sessions s83, s84, s85). Eleven ran; `s83-ordlimit2-20261002` was
prepared and never launched. This doc keeps the numbers that matter before
the raw data is pruned.

All cells: 3-validator loopback devnet on one 18-vCPU host, 5000 senders,
rate 76000 (effectively unbounded), cap 400, node env
`TORUS_BODY_FETCH_TRACE=1 RUST_LOG=info,libp2p_gossipsub::behaviour=error
TIMEOUT_BASE_MS=1200 TORUS_BODY_SERVE_THREAD=1 TORUS_DEFER_PARENT_FEED=0`
plus the per-campaign additions listed below. Warm-up cells are excluded
everywhere.

## Metrics

All numbers were recomputed from the cell files on 2026-10-03 (read-only
scorer, same method as `s84-5arm-20261003/score.py`):

- **matched/s**: `summary.json` headline `matched_s_avg` (bench window).
- **total (M)**: `torus_orders_matched_total` delta over [t_bench0, t_drain),
  mean over the 3 nodes (includes the drain).
- **best 60 s**: headline `matched_s_best60`.
- **CPU-s/1M**: node process CPU (pidstat process rows in
  `<campaign>/<label>-host/threads.log`) per 1M matched per node over
  [t_bench0, t_drain). Process total, not per-thread rows (s82 lesson).
- **submit/s**: `ingest.bench_submitted_actions` / bench wall seconds. A cell
  below 80% of its campaign median is flagged as a slow load generator.
- **phase timers** (flush, root, state write, dirty buckets, handoff wait,
  engine): `phase_by_node`, ms per native block, mean of the 3 nodes.
- **rejects %**: rejected / (rejected + accepted) from `funnel_by_node`.

Where these differ from earlier session records, the file values are used and
the difference is noted.

## 1. s83-markets-20260930 — market-count scan (uniform)

2026-09-30 23:27 to 10-01 00:11. Question: how does throughput fall with the
number of markets when every sender trades every market?

- torus-node `7b9013e0` (main 9c80e29, node code = a6917de; the s82 main
  artifact), bench-throughput `51e512e5` (s75).
- 300 s, uniform load (no MPS: main's generator still had the locality
  side-parity defect), 1 cell per market count + a 10-market warm-up. All
  AGREE / PASS.

| markets | matched/s | total (M) | best 60 s | CPU-s/1M | submit/s | flush ms | root ms | state write ms | dirty buckets / flush | handoff wait ms | engine ms | settle pass A ms | cache_flush ms |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 10 | 91.9k | 37.4 | 127.9k | 48.2 | 417 | 390 | 125 | 149 | 4.3k | 4 | 545 | 88 | 6 |
| 100 | 69.6k (-24%) | 28.9 | 97.4k | 66.3 | 352 | 1,248 | 579 | 447 | 29.0k | 137 | 920 | 247 | 63 |
| 300 | 49.5k (-46%) | 22.9 | 66.8k | 88.5 | 298 | 1,755 | 865 | 611 | 40.9k | 410 | 1,083 | 389 | 114 |

- Fills per native block are similar (81k / 104k / 97k), so this is a
  per-market cost, not block size. The exec queue is pinned (peak 64-66) in
  all three.
- The off-thread flush worker (trie root + state write) grows with markets
  and the exec thread waits on its handoff (4 → 137 → 410 ms per block).
  Engine settle also grows (pass A 88 → 389 ms).

**Verdict:** uniform-all-markets is the worst case: -24% at 100 markets, -46%
at 300. Next steps were a locality-shaped load (§2) and the root skip (§3).

**Caveats:** one cell per point, unpaired.

## Cross-campaign lessons

- Only compare interleaved cells from one window. The same binary moved
  49 → 43k and 54 → 69k across s83 by time of day, and the main arm was 58.4k
  in s84-4arm (d623d3c) but 49.7k in s84-5arm (199bdc9) with the same
  generator and config.
- Check the generator's submit rate per cell. Most outliers in these
  campaigns had a slow generator: regress new-r4 (174/s), s84-4arm main-r5
  (338/s), s84-5arm main-r1 (322/s).
- Score cap, load and code changes on total matched and CPU-s/1M (process
  total) as well as the window average.
- A DISAGREE verdict needs a check before it is read as a fork. In this set
  every DISAGREE was a harness artifact: the INFO fail-stop line (s83-hash),
  and a height spread of 6 > 5 (s83-regress rs-r3).
- Bench traps found in s83-s84:
  - `run-cell.sh`'s `pgrep -f 'cargo build'` aborts a cell when any command
    line contains that text.
  - The quiet-host check runs only at cell start.
  - A target dir shared between worktrees can serve stale artifacts.
  - perf symbols need `perf buildid-cache --add` when cells share the harness
    binary path.
  - `run_cell.py` reserves 6 + 0.2 x duration GiB (~66 GiB for 300 s).
- Release builds are reproducible: the same sha256 comes from any target dir
  (e.g. `335e8a0c` from both the running-hash branch and main d623d3c).
